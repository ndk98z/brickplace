# Worker scripts

- Three scripts: `gateway` (auth, routing, assets; holds no DOs), `game` (rule DOs),
  `realtime` (FanoutDO). Deploying a script restarts all of its DOs and drops their sockets,
  which is why FanoutDO lives alone in `realtime`.
- Each DO class is declared (and migrated) in exactly one script; others bind with
  `script_name`. Bindings do not inherit into `env.staging` / `env.production`: repeat them.
- `migrations` changes go in their own PR labelled `do-lifecycle` (checked in CI).
- Write to SQLite before replying, so the output gate makes the reply imply durability.
- Keep the Env interface in `src/index.ts`; `worker-configuration.d.ts` is generated by
  `pnpm types` (runtime types only) and never edited by hand.
- The gateway's top-level `ENVIRONMENT` is `locked`: `/ws`, `/api` and `/auth` stay closed
  unless `.dev.vars` sets `ENVIRONMENT=dev` (created from the example by `pnpm dev`) or an
  env block sets staging/production. Keep it that way. Only `dev` has the dev guest id
  (`?player=`) and the fake OAuth provider; elsewhere identity comes from the session (ADR 0015),
  plus staging's `bot-<n>` players behind the `BOT_KEY` secret (ADR 0034). Never widen that
  past staging.
- No secrets in `wrangler.jsonc` or code. Local secrets go in `.dev.vars` (gitignored);
  document new ones in `.dev.vars.example`.
- Worker tests run in the Workers runtime via `@cloudflare/vitest-plugin`; cross-script DOs
  are re-exported from `test/entry.ts` so one test Worker hosts them all.
